AdministrateMe V3 — harness architecture

Two machines. The chat agent runs while you are talking to it; GitHub Actions runs when you are not. Keeping them separate is the entire design.

Deterministic — no model can override it Plain code — classification, never judgement Stops for you — hard to reverse The product — rules and the wizard

Why the whole loop is one workflow run

The obvious build is separate workflows triggering each other: the implementer pushes, the push triggers the reviewer, the reviewer's comment triggers the repairer. Don't. claude-code-action authenticates as a GitHub App, so its commits do re-trigger workflows — the property that would make the chain work is the same one that runs it all night and produces a bill instead of a feature.

So the sequence is ordinary sequential steps inside one run. There is nothing to re-trigger. The repair budget is one round because one repair: "true" block is written into the file — not because a counter says 1. Raising it means editing YAML, which is the point: making an agent loop longer should be a deliberate act, not a number you nudge at midnight. Side benefit you will appreciate the first time something breaks — the whole thing is one log you read top to bottom.

Why lanes are drawn by blast radius, not confidence

A confidence threshold sorts on the one input the thing being judged can influence. Sort by how expensive the mistake is to undo instead.

LaneExampleCost of one bad mergePolicy
Reversible, containeda component, a style, a testone revertmerges itself
Reversible, widea policy matcher, an adaptera revert plus a re-runmerges at wide, stops at narrow
Hard to reversemigrations, auth, workflows, manifestsyou cannot cleanly undo itnever merges itself, at any mode

package.json is on the blocked list for a reason worth knowing: it holds the ci script, which is the pipeline's only gate. An agent able to edit that file can rewrite "ci" to "true" and every check passes forever, silently. Same for .github/. An agent that can rewrite its own guardrails does not have guardrails — and the failure is invisible, because everything stays green.

What it has not done

Run against a live repository. Three adversarial passes found 29 defects in these files first, four of which would have broken the first run outright — a shell-injection hole via issue title, missing browser binaries that would have failed every round forever, a git check blind to newly-added files, and a guard that cleaned the tree before checking it. Those are fixed; that is also the base rate. Run your first pipeline PR at mode = "shadow", where the full loop executes and merges nothing.
